# FCode Computer Use API

This document describes the legacy macOS application/background route. For runtime.desktop.available: true on darwin, follow macos-desktop-computer-use.md and use the separately confirmed computer.desktop route. Windows guidance is in windows-computer-use.md.

The legacy implementation targets macOS 14+ and requires a matching built Helper, a vision-capable model, system permissions, the official plugin enabled, a human selection submitted for the current turn, application authorization and a valid control lease. Availability and permission are separate. Windows uses its separate native runtime and platform guide. This route supports Native protocol 3 and compatible protocol 4 background routing. External apps support verified AX element actions and experimental window-addressed screenshot-coordinate mouse input, text and keys on compatible native windows. This requires the optional nativeWindowInput capability; it uses window-local event routing and never activates the target or moves the system pointer. AppKit fixture coverage does not prove all application compatibility: inactive Electron apps can ignore keyboard events, and controls can reject first mouse. Observe the effect after every dispatch. Website tasks use the normally installed Google Chrome in a dedicated headful task instance, with its real tabs and address bar. Main owns a private browser pipe and a fresh temporary profile; page click, move, scroll, drag, Unicode text and restricted keys use scoped browser input. Arbitrary protocol calls, evaluation, personal browser profiles and foreground activation are not exposed. Browser elementAction is unsupported. No automatic foreground fallback exists.

All methods return structured results. Observation methods automatically emit the screenshot to the model; do not print its base64. Initialize `setupComputerUseRuntime` at the start of every Node REPL cell.

| Method | Parameters | Result |
| --- | --- | --- |
| `computer.openBrowser({url})` | HTTP(S) URL without embedded credentials | creates one background normal Chrome task window; returns `{target:{appId,pid,windowId},...}` |
| `computer.requestCredential(params)` | `{stateId,elementIndex,origin}` | opaque `credentialId`, pending status; private native password UI |
| `computer.typeCredential(params)` | `{stateId,elementIndex,credentialId}` | one-use page input into the still-focused protected field; no secret returned |
| `computer.listApps()` | none | `apps`: current appId, pid, instanceId and name |
| `computer.openApplication(params)` | `{appId}` | returns `{target:{appId,pid},...}` after task consent and nonactivating installed-app startup |
| `computer.listWindows(target)` | `{appId,pid}` only, such as `opened.target` | `windows`: current window IDs, region and title |
| `computer.getAppState(target)` | `{appId,pid,windowId}` | screenshot plus `observation` with ID, image width/height, region, topology and AX elements |
| `computer.capture(target)` | `{appId,pid,windowId}` | screenshot plus observation, without AX elements |
| `computer.activateWindow(target)` | `{appId,pid,windowId}` | unsupported in product background routing |
| `computer.prepareInput(intent)` | `{method,params}` where method is a supported input wire name | optional one-use permit; no intended input is dispatched |
| `computer.click(params)` | `{frameId,x,y,button?:"left"\|"right"\|"middle",count?:1\|2\|3}` | dispatch state |
| `computer.move(params)` | `{frameId,x,y}` | dispatch state |
| `computer.drag(params)` | `{frameId,x,y,toX,toY,durationMs?:100..2000}` | dispatch state |
| `computer.scroll(params)` | `{frameId,x,y,deltaY,deltaX?}` | dispatch state |
| `computer.typeText(params)` | `{stateId,text,elementIndex?}` | Unicode input; max 16 KiB, no implicit clipboard fallback |
| `computer.pressKeys(params)` | `{stateId,keys:string[]}` | One non-modifier key, with optional modifiers |
| `computer.elementAction(params)` | `{stateId,elementIndex,action:"press"\|"focus"\|"set_value",value?}` | Supported AX action only |

Native application observations include `elementsTruncated` and `elementsTruncationReason`. AX collection batches supported public attributes and bounds child ranges; it retains the two-second, 300-element and 30-depth limits. A truncated tree does not prove that an omitted control is absent. Never guess omitted element indices or reuse an earlier snapshot; use a fresh supported observation or report the explicit bound. Protected values are never requested. Focus metadata is optional and collected for editing controls; use actual screenshots and state to verify other controls.

Pointer coordinates are integer pixels in the emitted screenshot, not global desktop coordinates. Use observation.width/height for the image size, even when browser coordinateSpace is page-css and the CSS region has a different size. For Chrome the Host maps them to the exact page CSS viewport; other applications use their Native window region. The Host rejects stale document, viewport, window geometry or monitor topology. Use `observation.id` for both frameId and stateId. Observe again after input, focus changes or dialogs; do not infer success from dispatch status.

Native menus can use a separate window. A parent screenshot does not give that popup its own input coordinates. Use fresh parent AX state and listWindows to correlate a unique same-process popup by current geometry, then capture that exact target and verify its real image before input. A cached or untitled window entry alone does not prove a visible popup. If the image is blank, padded incorrectly, shows a different surface or cannot be correlated uniquely, stop without clicking it. Move to an observed control and reobserve before clicking when hover is needed; do not invent activation or an AX fallback. Click popup options only from a fresh popup screenshot, then verify the effect in the parent window.

Input parameters may include `approvalId` from `prepareInput`. This optional compatibility sequence is not required for ordinary task-authorized input. Request a permit on a current observation, obtain another observation after approval, then execute the exact approved method and non-observation parameters in the same cell. The Host verifies new observation ordering, target/process/window, geometry, topology, image scale, element identity, permission revision and lease epoch. A confirmation cannot be reused, changed, transferred to another call or resumed from history. It expires within 120 seconds and no later than the current call. Keep the token in a local variable; never print it. This avoids consuming the final frame's 15-second lifetime during a human confirmation; older single-step input calls remain supported and may reject a frame that expires in the dialog.

Pass keys as an array of individual names: `pressKeys({stateId, keys:["CMD","A"]})` or `pressKeys({stateId, keys:["BACKSPACE"]})`. A string such as `"CMD+A"` is invalid and is rejected before dispatch. Normal Chrome keys support one letter/digit or `ENTER`, `TAB`, `SPACE`, `BACKSPACE`, `ESC`, `DELETE`, arrows, `HOME`, `END`, `PAGEUP`, `PAGEDOWN`. `CMD+A` and `CTRL+A` select text. Clipboard and address/tab/window shortcuts are rejected. The normal address bar is visible to the human; navigate through openBrowser and use screenshot coordinates for page controls. Ordinary typeText requires a focused unprotected input or textarea and does not accept elementIndex for Chrome.

For a requested installed Mac application, use openApplication with its bundle ID; Main resolves the actual installed identity and asks for task consent before startup. Existing unique instances are reused without reopening or activation. No executable path, launch arguments, environment, document or URL input is accepted. FCode/Helper and personal Chrome launch are rejected; websites use openBrowser. Both launch methods return a result envelope: use its `target` field for subsequent methods, never the whole result. For an authorized application task:

```js
const opened = await computer.openApplication({ appId });
nodeRepl.write(opened.target);
const windows = await computer.listWindows(opened.target);
nodeRepl.write(windows);
```

When using a listApps entry instead, extract only `{appId,pid}` for listWindows; extra fields such as name or instanceId are rejected. For openBrowser, capture or observe `opened.target`, which also includes windowId. Observe a current window before screenshot-coordinate input or explicit AX assistance. Startup retains non-activating configuration, process identity, permissions and cancellation checks; human pointer movement or foreground changes alone do not revoke the task. Do not automatically replay an uncertain launch. Stop revokes control and closes the Helper; ordinary Mac applications and their documents remain open for the human. The visible panel supports authorized application windows as well as the dedicated normal Chrome.

openBrowser uses a separate installed Chrome instance with its own temporary profile; it does not read or inherit personal Chrome cookies/profile. Only the owned browser process and profile are removed when its task ends. Window enumeration and capture include authorized offscreen windows where macOS supports their capture, without activating or unminimizing them. Listing apps does not authorize their contents. Application access is tied to a running process instance and the current user turn. The application dialog authorizes observation and supported input once for that task and process instance; ordinary inputs do not open another dialog. A new application, instance or human turn requires new consent. The Host does not reliably classify arbitrary business click semantics. Moved, replaced, expired, locked or unauthorized targets are rejected. Background AX input can operate an authorized window covered by another app, but still verifies that its element belongs to the observed window. It never falls back to foreground input. Foreground visibility alone does not signal takeover; use the trusted Takeover control.

The chat's stop/cancel action revokes the turn and releases held input independently of the ordinary queue. Canceling does not roll back completed effects. An uncertain dispatched browser input closes the task-owned browser before transfer; do not replay it. Completed effects are not rolled back. This SDK does not expose direct native transport, grant, lease or arbitrary evaluation methods.

Observations include `targetAppIsForeground` and `targetWindowIsForeground` (boolean or null). They are sampled native OS facts for the authorized target, not permissions or takeover intent. Null means unresolved. Showing or foregrounding the target does not pause automation; only trusted Pause/Takeover/Stop controls or independent lifecycle/safety failures revoke control. Continue with fresh observations while the task remains authorized. Direct human edits in that same window without Takeover may interleave with automation. External Native AX elements carry `parentIndex` within the same observation. A `press` on a static label/image can resolve its nearest registered button/link ancestor and returns `resolvedElementIndex`; disabled, changed or unsupported parents are rejected.

For enabled standard AXButton/AXLink controls, an explicit `press` invokes the standard AXPress API even if the current legacy action list omits it. Missing action metadata alone does not prove absence of the modern API. The OS may still reject it; observe the effect after dispatch, stop on uncertain results and do not replay. Other control roles require their advertised AXPress. The nearest containing standard control is never skipped.

Credential input requires the task-owned normal Chrome target, actual canonical HTTPS main-document origin, fresh observation and the same focused protected password node. requestCredential creates a private NSSecureTextField panel and returns no password. browser.credentialStatus reports none/pending/ready. Only the human can fill/confirm that panel; SDK requests against other Helper windows are denied. typeCredential consumes the reference before input and rechecks live main-document origin, document, viewport and protected field focus/identity before scoped browser input. The private Native response is consumed only by trusted Main; the value never enters SDK results, model prompts or logs. Reference binding includes lease epoch, process instance, window, origin and document and field identity; cancel, expiration, navigation and stop clear it. Do not replay on uncertain effects or put secrets in ordinary text methods. This API neither saves credentials nor reads a password manager.

For CMD+A in a supported non-secure text receiver, Native uses the public selected-text-range interface and reports inputBackend: ax-text-selection. Inactive AppKit applications may have no menu key-window target, so a dispatched raw shortcut alone does not prove selection. This assistance selects the current field without reading or replacing its complete value. A fresh getAppState may expose selection: {start, length} and characterCount on non-secure text elements; compare the selected length with the character count or verify the visible selection before deleting text. Other Native keys and text report native-window-events. Unsupported selection or uncertain effects do not trigger a second input route, activation, or global keyboard input.

External native mouse coordinates always use the emitted full-window PNG, including its title bar. Click the editing control, observe again, then use stateId for typeText or pressKeys. Native confirms the current keyboard receiver belongs to that exact process instance and window; ambiguous, changed or protected receivers are rejected. AX set_value explicitly replaces the entire value and is distinct from keyboard typing. Window-addressed events use an optional nonpublic system symbol and an empirically validated event subtype, so macOS upgrades and application-specific behavior require renewed acceptance. Missing capability returns unsupported_action, with no global input fallback. Drag is limited to the current observed window; cross-application drag is not provided. Stop releases held events to their original live process instance only.

Domain failures from a compatible official host reject with an Error carrying a stable `code`, such as `canceled`, `observation_stale` or `execution_uncertain`. Inspect `error.code` rather than parsing the message. Older hosts and ordinary bridge errors may have no code; report the actual failure and do not invent one. An error code is not a retry permit: uncertain input must never be replayed. No stack, broker credentials or arbitrary error properties cross the private Worker bridge.

## Model screenshot window and desktop action helper

The trusted Host identifies individual Computer Use images. The model keeps their latest three occurrences across calls and turns; earlier images and paired executable frame references are removed. User uploads and other generated images retain their existing unified compression policy. This never extends frame lifetime or input permission. `computer.desktop.act({method,params})` dispatches one documented desktop input using the supplied fresh frame, then calls getState and returns `{receipt,state}`. Both captures and effects remain subject to Main/Native validation. An error ends the sequence without input replay.
