# Computer Use

Use only the official Node REPL `mcp__node_repl__js` tool and this SDK. Each call uses a fresh Worker: initialize again in every cell. A plugin reference is a usage request, not application permission. Main validates the actual selected human turn and tool call; never invent selection metadata, change request context, start a Helper, or use shell/AppleScript/Playwright as a fallback for this capability.

Initialize every cell containing computer operations:

```js
const root = process.env.FCODE_CUA_PLUGIN_ROOT;
if (!root) throw new Error("Computer Use plugin root is unavailable");
const { join } = await import("node:path");
const { pathToFileURL } = await import("node:url");
const { setupComputerUseRuntime } = await import(pathToFileURL(join(root, "scripts", "computer-use-client.mjs")).href);
await setupComputerUseRuntime({ globals: globalThis });
```

Then use `computer` in the same cell. At the start of a task, print `nodeRepl.write({ pluginRoot: root, apps: await computer.listApps() })`. Use that actual root with the Read tool to load the platform guide and API document. `FCODE_CUA_PLUGIN_ROOT` belongs to the Node REPL Worker; do not assume it exists in Bash, guess paths, or search plugin caches. If the returned catalog's `runtime.platform` is `win32`, read `docs/windows-computer-use.md` under the same plugin root and follow that Windows workflow before any input. It replaces the Mac-specific launch, bundle ID, AX, CMD, browser and credential instructions below. Do not infer the controlled platform from the REPL process, a filename or a user setting. Existing Mac catalogs without runtime metadata continue the Mac workflow below. An unknown declared platform is unsupported.

## Efficient observation loop

Only the latest three authenticated Computer Use screenshots remain in model context. User-uploaded images and ordinary generated images keep their existing policy. Retained screenshots are visual history, not valid input frames: always observe fresh in the current cell before input.

For desktop tasks, use `computer.desktop.act({method,params})` with that fresh frame. It dispatches exactly one documented input and immediately observes again, returning `{receipt,state}`. Judge the post-action screenshot before choosing the next input. Do not spend another model round just to request the missing post-action screenshot. The helper never retries input or claims effect verification.

Known stable editing operations may share a cell, with a fresh observation between each input. Combine select-all and typing only after the actual editable field is focused and verified, with the same foreground application/window. Treat navigation, dialogs, unknown focus or any failure as a boundary requiring visual reconsideration. Never chain blind clicks or auto-submit an overwrite.

In the authorized desktop route, ordinary human mouse/keyboard activity or switching applications/pages does not cancel the task. Only physical Esc or trusted Pause/Stop expresses human interruption. Main automatically yields its own ordinary macOS FCode windows before observing. Keep pursuing the original goal from fresh screenshots after ordinary contention; do not ask for Continue or suggest keeping FCode hidden manually. `desktop.act` can return `receipt.status: "not_dispatched"` plus a fresh state when input was rejected before dispatch. End any remaining edit sequence, reconsider that screenshot and choose a new action; never claim success or replay old coordinates. Protected dialogs, system/permission failures and actual cancellation remain separate blockers.

For export/install progress, observe first. If it is complete, perform the authorized read-only artifact check and reply immediately; do not update a Todo just to create another model round. If progress remains, wait briefly (at most 5 seconds in a cell) and observe again. Never sleep 45 seconds before checking or run a long polling loop in Node REPL. A blocked observation requiring user action ends recovery: use the trusted Continue path after the obstruction is removed.

## Entry failures

If bootstrap or listApps fails with backend_unavailable, task_not_selected, task_inactive, permission_required, secure_input_active or missing runtime, preserve the fixed code/reason and stop after at most one controlled status recheck. A control_busy failure with requiresUserAction must stop without rechecking. Explain the required user action: use the trusted Continue computer task button, explicitly select Computer Use in a new message, rebuild/restart for missing resources, or grant the stated system permission. Do not search repositories, plugin caches or process/socket details. Do not call Bash, ffmpeg, AppleScript or another UI backend to complete a task that requires a particular application. A provider 403 is a model channel failure, not a native engine error. Never infer live permission from history or ask the model to reconstruct a broker.

## macOS desktop workflow

When listApps returns runtime.platform: darwin and runtime.desktop.available: true, read docs/macos-desktop-computer-use.md before any UI operation and use computer.desktop as the main task route. This route uses explicitly confirmed screen capture and real foreground input. It replaces the background instructions below for that task; do not mix routes. No application-specific controller is needed. Catalogs without desktop capability retain the limited background workflow below.

## macOS background workflow

For a requested installed Mac app, call `computer.openApplication({appId})` with its bundle ID. Main resolves the installed identity, requests task consent before launch and reuses an existing unique instance without reopening it. The response is an envelope: use `const opened = await computer.openApplication({appId}); await computer.listWindows(opened.target);`, not `listWindows(opened)`. The target field contains only appId and pid; do not pass extra fields from the full response or a listApps entry. Observe a current window before input. For example, the installed Apple Chess app has bundle ID `com.apple.Chess`; use fresh captures to locate the board and window-coordinate clicks or drags to play legal moves; AX may assist observation. Do not replace native-app tasks with a website. Do not guess PIDs/window IDs, run shell launchers, send app scripts or invent an unsupported input route. Uncertain startup must not be replayed automatically.

For an explicitly requested website task, call `computer.openBrowser({url})` to create a dedicated background window in the normally installed Google Chrome. Its response is also an envelope: print `opened.target` and pass that exact field to capture/getAppState, not the whole response. Do not reuse or take over the human's browser window. This window keeps Chrome tabs and its address bar. Main uses a private task-owned browser pipe for page screenshots and scoped input. No arbitrary DOM, JavaScript evaluation, CDP endpoint or Browser Use transport is exposed to the model.

The root FCode window shows a sampled preview and trusted pause, takeover, stop, and continue buttons. Continue creates a fresh explicitly selected human turn. When resuming a paused task, first list applications and windows and reuse its retained task-owned Google Chrome window if present; do not open a second browser. Obtain fresh state before all input. Old call IDs, observations, and credentials are invalid. The model cannot call private preview or window handover methods. Stop or ordinary completion closes the window; paused/taken-over windows expire after ten minutes.

Set the outer Node REPL tool argument `timeout_ms` to `120000` for every Computer Use cell. Application confirmations wait for a human; the ordinary REPL default may expire during that wait. The call still expires after 120 seconds and cancellation closes its confirmation. For an input cell, obtain fresh state in that same cell immediately before the input rather than reusing a frame from a previous model turn. A slow confirmation can still expire that frame; observe again and reconsider instead of extending it.

```js
nodeRepl.write(await computer.listApps());
// In the next cell, repeat bootstrap and use the actual appId and pid returned above.
nodeRepl.write(await computer.listWindows({ appId, pid }));
```

Read `docs/computer-use.md` under the same plugin root for the complete API. `getAppState` and `capture` automatically emit the real PNG to the model and return the associated observation. Use the returned `observation.id` as `frameId` or `stateId`. Element indices refer only to the current observation. External Native AX elements include parentIndex; use it to distinguish static labels from their real controls. Observations report targetAppIsForeground and targetWindowIsForeground as true, false or null. These are visibility metadata, not takeover intent. Do not pause merely because the target is visible, foreground or unresolved. Main stops execution for trusted Pause/Takeover/Stop controls and independent permission, lock, target, lease or lifecycle failures. Continue with fresh observations while authorized. Do not activate the target or fall back to global input. Direct human edits in the same target without Takeover may interleave with your actions.

Application access is approved once for the current human turn and running process instance. Ordinary input in that granted scope does not open another action dialog. Operate visually: observe the actual window, locate the visible control, send one screenshot-coordinate action, then obtain a new screenshot to verify its effect. For example:

```js
// Repeat bootstrap. Use integer pixels identified in the freshly emitted window PNG.
const fresh = await computer.capture(target);
nodeRepl.write(await computer.click({ frameId: fresh.observation.id, x: observedX, y: observedY }));
nodeRepl.write(await computer.getAppState(target));
```

Use fresh `stateId` for text, keys and AX input. Pass `pressKeys` an array of individual names, for example `{stateId,keys:["CMD","A"]}` or `{stateId,keys:["BACKSPACE"]}`; `keys:"CMD+A"` is invalid and rejected before dispatch. `prepareInput` is optional compatibility support for an exact one-use permit, not a required step for ordinary task-authorized input. If used, keep its token private, take a new observation, preserve the exact method and other parameters, and execute within the same cell. Never print or persist its token.

For CMD+A in a supported non-secure text receiver, Native uses selected-text-range assistance and reports inputBackend: ax-text-selection. This selects the current field without replacing its value or activating the app. Verify the visible selection or selection: {start, length} and characterCount from a fresh getAppState before deleting text. Other Native text and keys report native-window-events. Background menu compatibility remains application-specific; never claim an effect from a dispatch receipt.

The legacy application route fixes input routing to background. Compatible external native windows support screenshot-coordinate click, move, scroll and local drag through experimental window-addressed input, without moving the system pointer or activating the app. Click the visible editing control first, obtain fresh state, then use typeText or pressKeys; Native checks that the live keyboard receiver belongs to this window and is unprotected. AppKit input has dedicated fixture coverage, but not every application accepts background events without activating itself. Inactive Electron apps can ignore keys and controls that reject first mouse can ignore a click. Do not claim an effect from a dispatch receipt. Obtain a new screenshot, and report a limitation when the action has no visible effect. Never add a Command modifier to ordinary clicks or activate the app as a workaround. AX actions remain explicit assistance. Use `elementAction` with `press` for observed buttons/links, `set_value` with the complete intended field value for editable fields, and `focus` only when needed and supported. Select indices from the current AX tree and refresh them after every page transition. For a static label/image without its own AXPress, the Host can resolve the nearest registered button/link ancestor, checks it is enabled, and returns resolvedElementIndex. It refuses changed parentage and never skips the nearest control to press an outer one. An explicit press on an enabled standard AXButton/AXLink invokes the standard AXPress API even when the legacy action list omits it; the OS result and fresh observed effect still govern success. Missing metadata alone is not a reason to refuse such a standard control. Other roles require advertised AXPress. Stop on API failure or uncertain effects without replaying. `set_value` replaces the field value; it is not simulated caret typing. Do not print its value. A button may change the page after the action returns; observe its effect before selecting the next element.

Native menus can use a separate window. A parent screenshot does not give that popup its own input coordinates. Use fresh parent AX state and listWindows to correlate a unique same-process popup by current geometry, then capture that exact target and verify its real image before input. A cached or untitled window entry alone does not prove a visible popup. If the image is blank, padded incorrectly, shows a different surface or cannot be correlated uniquely, stop without clicking it. Move to an observed control and reobserve before clicking when hover is needed; do not invent activation or an AX fallback. Click popup options only from a fresh popup screenshot, then verify the effect in the parent window.

The dedicated normal Chrome window from `openBrowser` supports page `click`, `move`, `drag`, `scroll`, `typeText` and the documented subset of `pressKeys` through scoped browser input. Use screenshot coordinates and real editing for web fields. Browser `elementAction` and `activateWindow` are unsupported; use coordinates and let the human explicitly take control through the panel. Pass integer pixels from the emitted PNG, using observation.width/height. Do not pass CSS viewport coordinates or coordinates from the human preview. Chrome metadata coordinateSpace describes the Host-mapped CSS region; screenshot pixels may have a different size. The human preview includes the full real Chrome window. Ordinary typeText rejects password fields. Clipboard and browser window/address/tab shortcuts are unsupported. Drag supports local page pointer gestures only; native HTML5/file and cross-application drop are intercepted and unsupported. External native input uses the window-addressed compatibility route described above. Stop on unsupported_action or execution_uncertain; do not activate the target, change transports or fall back to global mouse/keyboard input. The SDK cannot select foreground routing. If the needed control is unavailable, observe and report the remaining limitation. Stop on user takeover. Do not send, buy, delete or change security settings outside the user's explicitly authorized business task.

Observe before input and immediately afterward. Use one logical input per cell until its effect is visible. Frames expire after 15 seconds; `prepareInput` allows a new frame after approval but does not extend any old frame. On `observation_stale`, take a fresh state and reconsider the action. On `execution_uncertain`, observe and report the uncertainty; never blindly replay input. A completed dispatch is not a successful business task. status: dispatched with effectVerified: false means observe the result; it is not execution_uncertain. If fresh observation confirms the intended field was missed, choose a corrected target from that new screenshot for a new action. Never retry uncertain or partially executed input.

The user may need to approve a new application or process instance once for this task. Never bypass these controls or describe the task as complete while waiting. Stop on user cancellation, permission denial, target changes or control contention. A new human turn must explicitly select the plugin again. Do not use this skill in automation or subagents.

Do not print credentials, screenshots as base64, full input text, or hidden/secure AX values. Keep completion reports tied to observed task effects. If a login page offers credential storage, do not save credentials unless the user explicitly requests it.

For login in the dedicated window, never put a password in a prompt, REPL cell, typeText, elementAction, output or clipboard. Click the observed password field, obtain fresh state, then call requestCredential({stateId,elementIndex,origin}) using the exact HTTPS origin from browser metadata. Print only its opaque reference/status. The human fills the private native credential panel; the SDK cannot observe or operate that panel. Observe the browser metadata until credentialStatus is ready. With fresh state and the still-focused secure field, call typeCredential({stateId,elementIndex,credentialId}). Observe afterward and submit the login through ordinary page click/keys. A reference is one-use, expires in 120 seconds and is canceled by stop/navigation. On pending or denial, report the actual state; never substitute plaintext input or claim login completed. The normal Chrome instance has a fresh private task profile, so no existing personal login is inherited; ending it removes the owned temporary profile. Unknown dispatched input closes only this task browser, so take a new task rather than replaying it.

When catching an SDK failure, preserve its `error.code` if present and its message. Compatible hosts keep stable domain codes; older hosts or ordinary transport errors can lack one. Do not infer a code from wording, treat missing codes as success, or replay uncertain input.
